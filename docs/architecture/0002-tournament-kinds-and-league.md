# ADR 0002: 大会の種類・ブキ記録・予選リーグ

- 状態: **採用**（2026-10-03 に開発者が方針と作る順番を了承。段階 1 から着手）
- 作成日: 2026-10-03

## 1. 背景

主催からのフィードバック（2026-10-03）と、そのヒアリング結果。

| # | 要望 | ヒアリング結果 |
| --- | --- | --- |
| A | ブキ統一杯は大会の一種。通常ルール大会か特殊ルール大会かを設定したい | 通常ルール大会はブキ自由なのでブキ表は不要。ただし後から記録として、各試合のブキ使用状況・使用率・貢献度が分かると嬉しい |
| B | 特殊ルールの種類 | カテゴリ縛り・ランダムブキ・サブ/スペシャル縛りをすべて計画している |
| C | 種類によって変えたいもの | 表彰画像の模様替えが最も現実的で、参加者のモチベーションも損なわない |
| D | ブキ統一杯のルールは「メインの種類を 2 つ選択」（マイナーチェンジは同じメイン扱い） | 1 ゲーム内でメンバーが別々のマイナーチェンジを持ってもよい |
| E | 予選・本選を作りたい | 予選はリーグ戦。規模・順位の決め方・BO 数は大会ごとに決めたい。本選はシングルエリミネーションでよい。ブキ使用制限は予選・本選を通算でよい（ただし制限が要る大会はあまり思いつかない） |

D はすでに実装した（候補の単位「メイン / ブキ」、混在したゲームは「〇〇系（混在）」で記録）。本 ADR は A・B・C・E を扱う。

## 2. 決めること

1. 大会の種類をどうデータに持つか（今後の特殊ルールを足しやすい形にする）
2. 通常ルール大会で「誰がどのブキを使ったか」をどう記録するか
3. 予選リーグをどうデータに持ち、本選トーナメントとどうつなぐか
4. 種類ごとの表彰画像の違いをどこまで作るか
5. 作る順番

## 3. 提案

### 3.1 大会の種類（`rules.kind`）

`Rules` に大会の種類を足す。種類ごとに「候補の登録」「使えるブキの判定」「表示する画面」「告知文」「表彰画像の装飾」を切り替える。

```ts
type TournamentKind =
  | 'free'      // 通常ルール（ブキ自由）
  | 'unified'   // ブキ統一杯（今の機能。候補の単位・再使用ルールはここだけで使う）
  | 'category'  // カテゴリ縛り   ← 詳細は要ヒアリング (5 章)
  | 'random'    // ランダムブキ   ← 同上
  | 'kit';      // サブ/スペシャル縛り ← 同上
```

- 設定のない今の大会は `unified` として読み込む（今と同じ動き）。
- 種類ごとの違いは `src/lib/kinds.ts` の 1 か所に表として持つ。
  例：`{ hasPool, showWeaponTable, recordPerPlayer, rulesText, awardDecoration }`。
  - 画面側は `kind === 'unified'` のような分岐を直接書かず、この表を見る。
  - 特殊ルールを足すときは、この表に 1 行足して、必要な判定を書くだけにする。
- `rules` は Firestore ルールで中身を検査していない map なので、**ルールの変更は不要**。

| 種類 | 候補の登録 | ブキ表 | 試合でのブキ記録 |
| --- | --- | --- | --- |
| 通常ルール | なし | なし（記録ページで代わりに集計） | 選手ごと（任意） |
| ブキ統一杯 | あり（メイン/ブキ単位） | あり | チームで 1 つ（混在はメインで記録） |
| カテゴリ縛り・ランダム・サブスペ縛り | 要ヒアリング | 要ヒアリング | 選手ごと（任意）を想定 |

### 3.2 選手ごとのブキ記録

通常ルール大会では、メンバーがそれぞれ違うブキを使う。今の `Game.weaponA`（チームで 1 つ）では記録できないので、選手ごとの記録を足す。

```ts
interface Game {
  weaponA: string;          // 今まで通り。チームで 1 つのブキ (ブキ統一杯)
  weaponB: string;
  /** 選手ごとの使用ブキ (Player.id -> ブキ ID)。未入力は null */
  picksA: Record<string, string> | null;
  picksB: Record<string, string> | null;
  ...
}
```

- 入力の手間を減らすため、**選手ごとの入力は任意**にする。前のゲームの内容を引き継ぎ、変わった人だけ直せばよい形にする。
- 集計（選手ページの「よく使うブキ」・勝率）は、選手ごとの記録があればそれを、なければチームのブキを使う。
- 新しく作る **「記録」ページ**（通常ルール大会ではブキ表の代わりに表示）：
  - 試合ごとのブキ一覧（ゲーム × 選手）
  - ブキ・カテゴリ別の使用率と勝率
  - チーム別・選手別の使用ブキ
- **貢献度は作らない**。キル数などの数値がなく、評価が主観になるため（開発者判断）。
  あとで必要になったら、ゲームごとに「MVP」を 1 人選べる程度にとどめる案がある。

### 3.3 予選リーグ → 本選トーナメント

大会に「予選リーグ」を任意で持たせる。予選のない大会は今と同じ動きになる。

```ts
interface League {
  groups: { id: string; name: string; teamIds: string[] }[];
  /** 各グループから本選に進むチーム数 */
  advance: number;
  bestOf: number;
  /** 順位の決め方 (上から順に比べる) */
  tiebreakers: ('wins' | 'gameDiff' | 'gamesWon' | 'headToHead')[];
  /** key: "L:<グループID>:<チームID>:<チームID>" */
  matches: Record<string, MatchRecord>;
}

interface Tournament {
  ...
  league: League | null;   // 予選なしは null
  bracket: Bracket;        // 本選 (今まで通り)
}
```

- **対戦表**：グループごとの総当たりを自動で作る（サークル方式で「第 n 節」に分ける）。各試合の記録画面は、今のトーナメントの試合記録画面を共通化して使う。
- **順位表**：勝ち数 → ゲーム得失差 → ゲーム取得数 → 直接対決（並び順は大会ごとに変更可）。最後まで並んだときは同順位として表示し、運営が手で並べ替えられるようにする。
- **本選へのつなぎ**：「本選トーナメントを作成」で、順位表から 1 回戦の枠を作る。
  - 別グループの 1 位と 2 位が当たるように並べる（たすき掛け）。作ったあとに枠を手で直すこともできる（今の機能）。
- **ブキの使用制限**：予選と本選を通算する（`teamUses` が予選の試合も含めるようにする）。
- **成績**：予選で敗退したチームは「予選敗退」として表彰・選手ページに出す。
- **規模・BO 数・進出数**は大会ごとに設定する。
- **Firestore ルール**：大会ドキュメントに `league` を足すので、`firestore.rules` の `validTournament` の許可キーに `league` を追加する。
  - ルールのテストも追加する。
  - **アプリを公開する前に `npm run deploy:rules` を実行する**（順番を逆にすると保存できなくなる）。

### 3.4 表彰画像の模様替え

今のテンプレート（ポップ / チーム色 / シンプル）はそのまま使い、**大会の種類ごとに装飾を足す**。

- 見出しの横に種類のリボン（「ブキ統一杯」「カテゴリ縛り」など）を入れる。
- 背景の模様を種類ごとに変える（例：統一杯＝同じアイコンの連続柄、通常＝インク飛び散り、ランダム＝「？」柄）。
- 通常ルール大会では、ブキ欄に「メンバーごとに一番使ったブキ」をアイコンの下に出す（3.2 の記録を使う）。

## 4. 作る順番

| 段階 | 内容 | ルール変更 |
| --- | --- | --- |
| 0 | （済）メイン単位の候補・マイナーチェンジの混在 | なし |
| 1 | （済）大会の種類（通常ルール / ブキ統一杯）・種類ごとの画面の出し分け・告知文 | なし |
| 2 | 選手ごとのブキ記録・「記録」ページ（使用状況・使用率・勝率） | なし（tournaments の中の変更） |
| 3 | 予選リーグ（対戦表・順位表・本選の作成・予選敗退の成績） | **あり**（`league` キー） |
| 4 | 表彰画像の種類ごとの装飾 | なし |
| 5 | カテゴリ縛り・ランダムブキ・サブ/スペシャル縛り（ルールの詳細が決まったものから） | なし |

1〜2 は通常ルール大会をすぐ開けるようにするため先に作る。3 は独立しているので、大会の予定に合わせて 1・2 と前後してもよい。

## 5. 未決事項（主催に確認したいこと）

特殊ルール（段階 5）は、作り始める前に種類ごとに次を確認する。

- **カテゴリ縛り**：
  - 縛るのは大会全体か、チームごとか、試合ごとか（例：「この試合はチャージャーのみ」）。
  - 誰がどう決めるか（運営が指定 / 抽選）。
- **ランダムブキ**：
  - アプリで抽選するか、ゲーム内の「ランダム」を使って結果を記録するだけか。
  - 抽選の単位は選手ごとか、チームごとか、試合ごとか。
- **サブ/スペシャル縛り**：
  - 「このサブを持つブキだけ」のような絞り込みか、「このサブ・スペシャルは禁止」か。
  - 1 ゲームごとに変わるか。

予選リーグ（段階 3）について：

- 1 グループの最大チーム数の目安（画面の作りに影響する。8 チーム程度まで想定）。
